## Judgment boundaries

### ASK before

- Deleting files or directories
- Changing public APIs / DB migrations / auth
- Adding new dependencies
- Force-pushing or rewriting git history

### ALWAYS

- Prefer editing existing files over creating new ones
- Match existing code style and patterns in the touched area
- Run relevant tests/lint for code you change when practical
- Keep diffs focused on the requested task

### NEVER

- Commit secrets, `.env`, or credentials
- Invent APIs or file paths that do not exist — check the repo first
- Disable tests or linters to “make it pass”

## Code style

- Follow existing formatter/linter config in the repo
- Do not restate rules already enforced by tools
